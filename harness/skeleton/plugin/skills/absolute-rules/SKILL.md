# 절대 규칙

## 0. 이 문서의 지위
- 여러 규칙이 부딪히면 이 문서가 이긴다. 이 문서를 바꾸려면 {{owner}} 승인이 필요하다.
- 사실(명령 · 파일 · 설정 · 데이터)의 주인은 코드 · DB · git 이다. 기준(한도 · 요금 · 권한 · 완료 기준)의 주인은 문서다.

## 1. 불변 완료 기준
- 확인하지 않은 것을 됐다고 쓰지 않는다. 커밋 ≠ push ≠ 배포 ≠ 동작.
- 완료의 증거는 테스트 · 검사 명령 · 조회 결과의 출력이다. 「통과했다」는 말만 있으면 검증 없음이다.

## 3. 드리프트 방지 규칙
- R1. 기준은 문서 먼저 → 코드. 코드만 바꾸고 문서를 두지 않는다.
- R2. 값에는 누가 · 언제 · 어떻게 쟀나를 붙이고 재는 명령을 적는다.
- R3. 추정은 추정이라고 쓴다. 관찰과 추론을 갈라 적고, 못 쟀으면 「미확인」.
- R4. 한 번 정한 결정을 대화 기억으로 뒤집지 않는다. 결정 기록(이슈 · docs/기록/)을 먼저 본다.
- R5. 유료 호출(외부 API · 생성 모델)은 사용자가 결과를 실제로 볼 때만 나간다. 붙이기 전에 누가 · 언제 · 얼마 · 끄는 법 네 가지를 적는다.

## 4. 새 지시 충돌 경고
새 지시가 1 · 2 · 3절과 부딪히면 바로 따르지 말고 이 형식으로 먼저 알린다.
```
충돌 경고: <지시> 는 <규칙 자리> 와 부딪힌다.
지금 기준: <값> (근거)
선택지: ① 기준을 바꾼다(문서 먼저) ② 이번만 예외 ③ 지시를 거둔다
```

## 5. 결정 요청 형식
- {{owner}}께 결정을 물을 때는 선택지(2~4개)로 묻고, 권하는 것을 첫째에 둔다.
- 값에는 근거를 붙이고, 추정은 추정이라고 쓴다.
