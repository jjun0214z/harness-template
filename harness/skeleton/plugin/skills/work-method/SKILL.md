# 작업 방식 (측정 · 판정 · 기록 · 보고)

## 1. 기록의 자리

<!-- harness:end work-method-records -->
- 규칙과 기록을 가르는 기준 한 줄: **이 글이 바뀌면 다음 세션의 행동이 바뀌는가.** 바뀌면 규칙(스킬 · `CLAUDE.md`), 아니면 기록(`docs/기록/`).
- 인용될 값만 남긴다. 일회성 디버깅 출력은 남기지 않는다.
- 작업자는 기록 문서를 쓰지 않는다. 보고로 돌려주고 오케스트레이터가 남긴다.

## 2. 상태 · 값을 적는 형식
- 값 = 숫자 + 누가 + 언제 + 어떻게(명령). 예: `응답 210ms (조사원, 2026-01-02, curl -w %{time_total} …)`.
- 근거 등급: ① 직접 잰 출력 ② 코드 · 설정 파일과 줄 ③ 문서 ④ 추정. ④는 「추정」이라고 쓴다.

## 3. 판정 규칙
- 통과 / 미통과 / 미확인 셋만 쓴다. 「대체로 통과」는 없다.
- 부분 통과는 미통과다. 무엇이 남았는지 적는다.

## 4. 검사 장치를 다루는 규칙
- 새 검사는 일부러 틀린 입력으로 한 번 떨어지는 것을 보고 믿는다.
- 검사를 끄거나 느슨하게 할 때는 이유와 되돌릴 조건을 적는다.

## 5. 사람에게 묻고 보고하기
- {{owner}}께는 짧게 · 표와 굵은 글씨로. 결정이 필요한 것은 선택지로 묻는다.
- 보고 끝에 무엇이 남았는지 적는다. 확인하지 않은 것은 「미확인」이라고 쓴다.

## 6. 버그 · 개선 목록
- 이슈 하나 = 문제 하나. 재현 절차 · 기대 · 실제 · 근거를 적는다.

## 7. 모르는 것
- 추측으로 메우지 않는다. 재지 못했으면 「미확인」이다.
- 문서에 적을 때는 그 문서 끝 「확인 필요」 절로 뺀다. 본문에 추정을 섞지 않는다.
