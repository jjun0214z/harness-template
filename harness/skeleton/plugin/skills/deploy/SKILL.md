# 배포

**push 는 오케스트레이터만 한다.** 플러그인 push 가드가 강제 push 를 막고, 아래 표에서 「묻는다」인 push 는 {{owner}}께 묻는다.
Codex 는 승인 질문을 지원하지 않아 승인 전 push 를 막는다. {{owner}}이 승인한 뒤에만 명령 앞에 `HARNESS_APPROVED_PUSH=1` 을 붙여 다시 실행한다.

## 1. push 전 (묻는 게 아니라 잰다)
- [ ] 작업자 보고의 검증 출력을 확인했고 `reviewer`(검토원) 판정이 「통과」다.
- [ ] 저장소 **전체** 검사가 통과했다(아래 표의 검사 명령). 출력이 없으면 검증 없음이다.
- [ ] `git -C <저장소> log --oneline origin/<기준>..<밀 SHA>` 에 내 커밋만 있다.

   정리 스크립트는 변경 없음 · 원격에 없는 커밋 0 · 그 작업자가 busy/응답 대기가 아님 · 부른 세션 자신의 워크트리가 아님을 전부 확인하고, 하나라도 모르면 멈춘다(`--dry-run` 으로 미리 본다).
   세션 파일을 못 읽거나, pid 가 claude 가 아니거나(재사용된 pid), 실제 작업 폴더가 워크트리 밖이거나, 세션 파일 없이 워크트리를 쓰는 프로세스가 있으면 멈춘다.
   쉬는 세션의 자식(MCP 서버 등)과 세션 바로 위 셸(터미널 · bash -c)은 허용한다. 순서: 세션 정상 종료 → (Orca) worker-release → 워크트리를 쓰는 프로세스 0 확인 → Codex 보관 → 워크트리 삭제.
   사람이 연 터미널이 남아 있으면 「그 터미널을 닫고 다시 부른다」로 멈춘다(터미널은 끄지 않는다).
   Claude 작업자는 정상 종료(SIGTERM)만 하고, 안 끝나면 멈추고 보고한다. 끝에 「앱 보관 대상(Claude): <작업 이름> · <bridgeSessionId>」 를 출력한다(ID 는 종료 전에 세션 파일에서 읽는다).
   동시 정리는 잠금 파일(`<프로젝트 폴더>/.work/cleanup.lock`, pid · 시작 시각)로 막는다. 잠금이 살아 있으면 멈춘다.
   **남은 프로세스**: 세션을 끝낸 뒤에도 남은 작업자 도구(`node` · `next` · `pnpm` · `adb` · `python` 등, 워크트리를 작업 폴더로 쓰거나 명령줄에 워크트리가 든 것)와
   이 작업 전용 검수 크롬(프로필이 워크트리 · 그 Claude 임시 폴더 안이거나 이름에 작업 이름이 든 것)은 끈다(`끔 : pid …` 줄). `--dry-run` 의 `끌 것(지금 기준)` 줄로 미리 본다.
   에이전트(claude · codex, node 로 도는 것 포함) · 셸 · 이름 모르는 프로세스 · 프로필 없는 크롬 · 기본 프로필(`~/Library` · `~/.config`) 크롬 · crashpad 는 끄지 않는다.
   **휴지통**: 정리 스크립트는 휴지통으로 보내지 않고 바로 지운다. 미리보기 끝의 `크기만 휴지통` 줄은 크기와 찌꺼기로 보이는 항목 수만 보인다. 휴지통 비우기는 {{owner}}께 말씀드려 직접 하시게 한다(개인 파일이 섞여 있을 수 있다).
② Codex: 정리 스크립트가 `codex archive` 로 자동 보관한다. 실패는 경고만 하고 정리는 계속한다.
   보관이 성공해도 Codex 데스크톱 앱 「최근」에는 남을 수 있다(앱이 자기 안에 띄운 앱서버로 목록을 들고 있어 바깥 CLI 보관이 바로 반영되지 않는 것으로 보인다. 추정).
   정리 출력의 `앱 보관 대상(Codex): <작업 이름> · <thread id> · 「제목」 · 시작 <시각>` 줄을 모아 {{owner}}께 「Codex 앱 → 해당 프로젝트 → 그 시각의 항목 → 보관」을 표로 부탁드린다.
   작업자 세션은 제목이 서로 비슷할 수 있으니 제목만으로 고르지 않고 프로젝트 · 시작 시각으로 맞춘다.
   Claude 샌드박스 안에서는 `codex archive` 가 파일 시각 설정(set_times)에서 실패할 수 있다. 그때 나오는 `다시 보관:` 명령을 사용자 터미널(`! <명령>`)에서 한 번 더 돌린다.
③ Claude 앱 · 웹 · 폰의 원격 세션 목록은 스크립트로 보관할 공개 방법이 없다. 목록 제목은 자동 생성이라 작업 이름으로는 못 찾는다.
   오케스트레이터가 브라우저 도구(Claude in Chrome 등)로 claude.ai/code 를 열어, **링크 href 가 `/code/<bridgeSessionId>` 인 항목만** 찾는다
   (ID 는 ① 의 「앱 보관 대상(Claude): <이름> · <bridgeSessionId>」 줄에 있다). 그 항목이 「오프라인」인지 확인한 뒤 ⋮ 메뉴 → 「보관」(삭제가 아니다).
   **남길 것**: 지금 정리를 하는 호출 세션 자신 · 사용자가 직접 연 세션(대상 목록에 없는 ID 전부) · 온라인(연결됨 · 실행 중)인 행.
   화면 클릭이 빗나가면 같은 순서를 JS 로 밟는다. 사이드바의 `a[href="/code/<ID>"]` 에서 위로 올라가며 「…에 대한 더 많은 옵션」 버튼
   (`button[aria-label$="더 많은 옵션"]`, 영어 화면은 `More options`)이 든 가장 가까운 행을 찾는다. 다른 세션 링크(`a[href^="/code/"]`)가 둘 이상 든 상자까지 올라가면 멈춘다(남의 행 클릭 방지).
   그 버튼을 누르고, 열린 메뉴의 `[role="menuitem"]` 중 글자가 「보관」(`Archive`)인 것을 누른다. 「삭제」는 누르지 않는다. 누른 뒤 그 링크가 목록에서 사라졌는지 다시 재서 확인한다.
   같은 ID 의 항목이 없으면 아무것도 하지 않는다. 온라인 · 응답 대기면 건드리지 않는다. 세션 ID 를 모르면(「세션 ID 모름」 줄) 브라우저 단계는 건너뛰고 보고한다.
   브라우저 도구가 없으면 {{owner}}께 보관할 세션 ID 목록만 알린다. 정리 잠금이 있거나 다른 오케스트레이터 세션이 동시에 정리 중이면 하지 않는다.
